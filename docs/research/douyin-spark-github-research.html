01结论先行

如果你只想要一个答案，按使用场景直接选：

S 级 · 首选长期维护、功能闭环、部署文档完整

① 要功能最全、能长期挂着 → halfwaystudent/douyin-sparkflow（574★，10-20 仍在提交，近 90 天 100+ 次提交）

Docker 五容器编排（面板 / 调度 / 扫码桌面 noVNC / Mihomo 代理 / 一次性任务），多账号、发送时间窗口、限流间隔、一言与节日模板全都有。代价是部署最重，且许可证为 PolyForm 非商业。

② 要开箱即用又不想背非商业许可 → 2061360308/DouYinSparkFlow（415★，10-16，100+ 次提交，MIT）

图形化客户端 + Docker + 挂机宝三形态，装完点几下就能跑，对不熟命令行的用户最友好；作者文档站与 QQ 群都在持续维护。

A 级 · 场景最优某一方面明显更强，值得为它妥协

没有服务器、想让别人机器跑 → unmev/douyin-auto-fire（410★）：GitHub Actions / Docker / systemd / Windows 计划任务四种跑法，支持文字 + 图片 + 抖音原生表情，带 Dry Run、防重复、钉钉与通用 Webhook 通知，是"零服务器"路线里工程完成度最高的。

想要代码干净、好改 → Xiaowu-0916/douyin-spark（76★）：FastAPI + Playwright + APScheduler 单服务，一个 deploy.sh 上 Debian/Ubuntu，1 核 1G 可跑，发送有三段校验、失败 45 分钟补发、命中"操作频繁"立刻熔断，是同类里防护逻辑写得最细的。

需要给"从没聊过天"的好友发首条 → diyiqiuye/douyin-keeper（21★）：在 Xiaowu 版基础上加了 creator 创作者中心通道，consumer 通道发不了的新好友也能处理。

B 级 · 可用但有短板能跑，但门槛、平台限制或工程质量有折扣

只开浏览器、不装环境（油猴脚本） → dr-190/ScriptCat-Douyin-Fire-Helper（127★）：装 Tampermonkey/ScriptCat 后在 douyin.com/chat 上跑，功能其实很丰富（火花天数占位符、按周几配专属文案、跨天随机时间、10 分钟重试）。但需浏览器常开，且 README 主推作者的付费云平台，开源与商业混合。

macOS 原生应用 → lazymicezhu/DouyinFire（54★）：唯一把"发送结果不确定"做成状态机的项目（已发送/已跳过/未发送/待核实），睡眠唤醒后 180 分钟补跑窗口；仅 macOS，且要自己从源码 build。

Windows 桌面双击即用 → baiyingawa/AutoDouyinSpark（18★）：Electron + React 桌面端，8 路并发、火花天数趋势图、发送截图回放、Cookie 到期邮件提醒。

前后端分离、想接自己系统 → DkoBot/TikTokAutoSparkWeb（94★）：Vue3 管理端 + FastAPI 后端（9844 端口），接口清晰；但默认口令 admin/123456 必须改，且没有一键部署脚本。

C 级 · 不建议新用

已自认失效 → bling-yshs/douyin-auto-spark（103★）：工程规范最好（TS + 类型检查 + lint + Docker），但仓库描述直接写了"已被风控失效"，README 表格里 GitHub Actions 方式标注"抖音风控严重，基本不可用"，最后提交停在 09-16。可读性值得学，直接拿来用价值低。

手机端脚本（AutoJS6） → KID-1912/autojs6-douyin-sendMessage（84★，2024-03 后无更新）、COLDESTBOW30654/Automatic-spark-renewal（4★）：免 root 用无障碍权限在手机上定时发消息，适合"完全不想开电脑"的人，但两年未更新、依赖界面元素定位，抖音一改版就废。

halfwaystudent / douyin-sparkflow

574★ · 2026-10-20 · 90 天 100+ 提交 · 谱系：与 2061360308 版同源重构

05横向看出来的四件事

1. 技术路线只有四条，选路线比选项目重要

  • 桌面/服务器浏览器自动化（Playwright / Selenium）——占绝对主流，稳定性和可控性最好，代价是要一台常开机器。S/A 级项目全在这条线上。
  • GitHub Actions 无服务器——最省事，但机房 IP 是硬伤。多个作者已用行动承认：halfwaystudent 直接删掉了 GHA 发送工作流，bling-yshs 在 README 里给 GHA 打"基本不可用"。
  • 油猴脚本——不装环境，但必须浏览器常开，适合本来就让电脑不关的人（dr-190）。
  • 手机无障碍（AutoJS6）——设备最省，但纯靠界面元素定位，最脆弱，且主力项目已停更。

2. 没有一个项目能"装完就不用管"

所有项目都依赖抖音网页版的登录态（Cookie / storage_state），有效期普遍是几天到几周。过期后必须本人重新扫码——这是抖音服务端的策略，不是代码缺陷（wydddddcool 的 README 把这点写得很直白）。所以评估时真正该看的是"掉线后恢复有多麻烦"：Xiaowu / diyiqiuye 是网页标红再上传一个 json；halfwaystudent 与 HRuiCcc 可以在面板里直接重新扫码，明显更省事。

3. Star 数会骗人，同源代码很多

这次检索到的 19 个仓库里，至少能看出两条明显谱系：2061360308 系（halfwaystudent 的内部目录仍叫 DouYinSparkFlow，BTHawake、cosinXx 明确标注"由它修改而来"）与 FastAPI 系（Yuriz132 教程 → Xiaowu-0916 → diyiqiuye / HRuiCcc）。同源项目之间的差异往往只是皮肤和补丁，跨谱系比较才有意义。另外 star 高不等于现在能用：103★ 的 bling-yshs 已经自认失效，84★ 的 KID-1912 停在 2024 年。

4. 许可证差异会直接影响你能不能商用

  • PolyForm Noncommercial 1.0.0：halfwaystudent、unmev——个人学习自用可以，收费服务、代运营、客户账号管理、商业账号维护全部禁止，需要单独书面授权。
  • MIT：2061360308、Xiaowu、diyiqiuye、DkoBot、BTHawake、cosinXx——最宽松，二次开发限制最少。
  • GPL-3.0：bling-yshs——衍生分发需同样开源。
必须说清的风险。以上所有项目都通过自动化手段发私信，这与抖音社区公约中"未经平台允许使用自动化手段发消息"的规定相冲突，多位作者在 README 里明确写了可能导致限流、功能限制、账号封禁。此外 state.json / Cookie 等同于账号凭据，一旦泄露等于账号被接管——不要提交到公开仓库，也不要用来源不明的"代部署"服务。项目方普遍建议：只操作本人账号、少量好友、每天一条、先用小号试。

06怎么选：一份决策清单

  1. 我有国内云服务器 / NAS，愿意花半小时部署 → 先试 halfwaystudent/douyin-sparkflow；如果嫌 Docker 五容器太重，退到 2061360308/DouYinSparkFlow 的 Docker 镜像。
  2. 我想要代码干净、能自己改，或者要接自己的系统 → Xiaowu-0916/douyin-spark（单服务、deploy.sh 一把梭）或 HRuiCcc/dy-xuhuohua（内建扫码 + REST API 文档齐全）。两者都 MIT。
  3. 我没有服务器，电脑也不能常开 → unmev/douyin-auto-fire 的 GitHub Actions；但要接受"可能被要求验证码、可能发不出去"的概率，并且别把主账号的 Cookie 放上去。这是所有方案里唯一真正零成本的，也是风控暴露面最大的。
  4. 我电脑本来就常开，只想装个脚本 → dr-190 的油猴脚本（Chrome 常开 + chat 页面）比装 Python 环境省事得多。
  5. 我只用 Windows 桌面 → baiyingawa/AutoDouyinSpark（双击安装包）或 2061360308 的图形化版本。
  6. 我只用 macOS → lazymicezhu/DouyinFire，唯一对"发送结果不确定"做了显式状态管理的项目，最不容易出现"以为发了其实没发"。
